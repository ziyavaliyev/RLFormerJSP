# RLFormerJSP

RLFormerJSP is a reinforcement learning framework for solving the **Job Shop Scheduling Problem (JSP)** using attention-based policies and graph representation learning.

The repository investigates whether latent graph representations learned by **Graph Autoencoders (GAE)** and **Variational Graph Autoencoders (VGAE)** can improve reinforcement learning performance compared to handcrafted scheduling features and graph-based baselines.

# Overview

The project consists of three main stages:

```text
JSP Instances
      │
      ▼
Validation Dataset Creation
(OR-Tools + Baselines)
      │
      ▼
Graph Representation Learning
(GAE / VGAE)
      │
      ▼
PPO Training
      │
      ▼
Performance Evaluation
```

The reinforcement learning agent can operate on different observation representations:

| Representation | Description |
|---------------|-------------|
| handcrafted | Hand-engineered scheduling features |
| graph_features | Additional graph-derived features |
| raw_graph | Raw graph representation |
| encoder | Latent embedding generated by a pretrained GAE/VGAE |

# Configuration System

All experiments are controlled through YAML configuration files located in:

```text
configs/
```

Each instance size has its own configuration:

```text
ppo_6x6.yaml
ppo_10x10.yaml
ppo_15x15.yaml
ppo_20x20.yaml
```

Most experiments can be reproduced by modifying only the configuration file.

---

# Validation Datasets

Before PPO training, a validation dataset must exist.

A validation dataset contains:

- Validation JSP instances
- OR-Tools solutions
- Baseline scheduling results
- Summary statistics

These datasets are used during training to compute:

- Validation makespan
- Optimality gap
- Best checkpoint selection

Existing datasets are stored in:

```text
data/
```

Examples:

```text
data/val_dataset_6x6.pt
data/val_dataset_10x10.pt
data/val_dataset_15x15.pt
data/val_dataset_20x20.pt
```

---

# Creating a New Validation Dataset

When introducing a new problem size, a validation dataset must be generated first.

Example:

```yaml
data:
  n_jobs: 30
  n_machines: 30
  n_val_instances: 100
```

Then run:

```bash
python scripts/create_val_dataset.py \
    --config configs/ppo_30x30.yaml
```

The script automatically:

1. Generates validation instances
2. Solves them with OR-Tools
3. Computes baseline statistics
4. Stores the dataset in `.pt` format

---

# OR-Tools Baseline

OR-Tools is used as the primary reference solver.

The validation performance is measured using:

```text
optimality_gap_percent
=
(model_makespan - ortools_makespan)
/
ortools_makespan
× 100
```

The main optimization metric used in experiments is:

```text
best_optimality_gap_percent
```

rather than the final training performance.

# Observation Modes

The observation representation is controlled through:

```yaml
observation:
  mode: handcrafted
```

Available modes:

```text
handcrafted
graph_features
raw_graph
encoder
```

For encoder-based representations:

```yaml
observation:
  mode: encoder

encoder:
  path: trained_encoder_weights/10x10/vgae_gatv2.pt
```

# PPO Training

Training is performed using:

```bash
python scripts/train_ppo.py \
    --config configs/ppo_10x10.yaml
```

---

# Running Individual Representations

Handcrafted baseline:

```bash
python scripts/train_ppo.py \
    --config configs/ppo_10x10.yaml \
    --representation handcrafted
```

Encoder representation:

```bash
python scripts/train_ppo.py \
    --config configs/ppo_10x10.yaml \
    --representation trained_encoder_weights/10x10/vgae_gatv2.pt
```

# Weights & Biases Sweeps

The repository supports automated representation comparisons using W&B sweeps.

Create a sweep:

```bash
wandb sweep sweeps/sweep_10x10.yaml
```

Run an agent:

```bash
wandb agent <SWEEP_ID>
```

Typical sweeps compare:

- handcrafted
- graph_features
- raw_graph
- all GAE encoders
- all VGAE encoders

under identical PPO settings.

# Adding a New JSP Instance Size

To run experiments on a new size, for example:

```text
30x30
```

follow these steps:

### 1. Create a configuration file

```yaml
data:
  n_jobs: 30
  n_machines: 30
```

### 2. Generate a validation dataset

```bash
python scripts/create_val_dataset.py \
    --config configs/ppo_30x30.yaml
```

### 3. Train graph encoders

Store the resulting weights in:

```text
trained_encoder_weights/30x30/
```

### 4. Update encoder paths

```yaml
encoder:
  path: trained_encoder_weights/30x30/gae_gatv2.pt
```

### 5. Train PPO

```bash
python scripts/train_ppo.py \
    --config configs/ppo_30x30.yaml
```
